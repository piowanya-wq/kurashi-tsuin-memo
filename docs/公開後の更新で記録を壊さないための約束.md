# 公開後の更新で記録を壊さないための約束

作成日: 2026-07-21
作成担当: Codex
最終更新日: 2026-07-21 (Codex)

## このアプリの約束

利用者の記録は、各端末のブラウザ保存領域（IndexedDB）に入る。更新で既存の記録を読めなくしたり、勝手に消したりしない。

## 初期項目を変える時の約束

初期項目（外出、仕事、入浴、体調不良など）をコードから削除すると、すでにその項目を使っている人の過去記録が画面や通院メモに出なくなる可能性がある。

- 初期項目の保存キー（例: `outing`、`work`、`bath`、`condition`）を削除・改名しない。
- 項目を新しく増やすのはよい。
- 今後表示したくなくなった初期項目は、画面から隠せる「廃止項目」として読み取りだけを残す。
- 完全に廃止したい時は、既存利用者の記録を読み直して別の項目へ移す処理と、事前の案内を必ず用意する。

## 保存のしくみを変える時の約束

- データベース名 `kurashi-tsuin-memo-db` は変えない。
- `entries` と `settings` のテーブル名、`entries` の日付キー `date` は変えない。
- すでに保存した項目名・型を削除や変更しない。不要な項目は画面から隠し、読み取りは残す。
- データベースの版を上げる時は、Dexie の移行処理で古い記録を新しい形へ安全に変換する。
- JSONの `app`、既存のフィールド、過去の版を読み込む処理を理由なく壊さない。

## 更新する時の手順

1. 既存利用者の記録がある前提で、コピーしたブラウザデータまたはJSONで試す。
2. `npm run build` を通す。
3. JSONを書き出して、次の版で読み込み直せることを確認する。
4. 項目の削除ではなく、非表示・廃止として扱う。
5. 破壊的な変更が必要なら、新しい保存領域へ移す手順と、利用者への案内を先に用意する。
